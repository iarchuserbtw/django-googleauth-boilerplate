# Database Administration Interfaces

Веб-интерфейсы для просмотра, администрирования и отладки базы данных во время разработки.

> **Важно:** эти сервисы в первую очередь предназначены для локальной разработки и администрирования. Не следует без необходимости публиковать их порты в production.

## Быстрое сравнение

| Инструмент | Лучше всего подходит для | PostgreSQL | Другие БД | Сложность | Интерфейс |
|---|---|:---:|:---:|:---:|:---:|
| **pgAdmin** | Полное администрирование PostgreSQL | ✅ | ❌ | Средняя | ⭐⭐⭐ |
| **Beekeeper Studio** | Удобная повседневная работа с SQL | ✅ | ✅ | Низкая | ⭐⭐⭐⭐⭐ |
| **CloudBeaver** | Универсальный web-интерфейс / работа команды | ✅ | ✅ | Средняя | ⭐⭐⭐⭐ |
| **Adminer** | Максимально простой и лёгкий DB UI | ✅ | ✅ | Очень низкая | ⭐⭐ |

# pgAdmin

Официальный и один из наиболее функциональных инструментов администрирования PostgreSQL.

Подходит, если нужен не только просмотр данных и выполнение SQL, но и полноценное управление PostgreSQL: схемами, ролями, индексами, backup/restore и другими объектами базы данных.

### Docker Compose

```yaml
pgadmin:
  image: dpage/pgadmin4:latest
  container_name: pgadmin

  environment:
    PGADMIN_DEFAULT_EMAIL: admin@admin.com
    PGADMIN_DEFAULT_PASSWORD: adminpassword

  ports:
    - "5050:80"

  restart: unless-stopped
```

После запуска:

```text
http://localhost:5050
```

При подключении к PostgreSQL, находящемуся в том же Docker Compose:

```text
Host: db
Port: 5432
```

Используй имя Docker Compose-сервиса (`db`), а не `localhost`.

### Плюсы

- Специализирован именно под PostgreSQL.
- Очень много административных возможностей.
- Управление databases, schemas, tables, views, indexes, roles и другими объектами.
- Встроенный SQL Query Tool.
- Поддерживает backup и restore.
- В контейнере доступны PostgreSQL-инструменты вроде `pg_dump`, `pg_restore` и `psql`.
- Хорошо подходит для изучения возможностей PostgreSQL.
- Open Source.
- Может работать как полноценный серверный web-интерфейс.

### Минусы

- Интерфейс довольно тяжёлый.
- Запускается и работает тяжелее минималистичных альтернатив.
- Для простого просмотра таблицы может ощущаться избыточным.
- Требует отдельной авторизации в самом pgAdmin.
- Ориентирован практически исключительно на PostgreSQL.

### Когда выбирать

Если проект использует **PostgreSQL** и нужен полноценный инструмент администрирования — это один из наиболее логичных вариантов.

# Beekeeper Studio

Современный SQL-клиент с акцентом на удобный интерфейс и повседневную работу разработчика с базами данных.

### Docker Compose

```yaml
beekeeper:
  image: beekeeperstudio/beekeeper-studio:latest
  container_name: beekeeper-studio

  ports:
    - "3000:3000"

  restart: unless-stopped
```

После запуска:

```text
http://localhost:3000
```

### Плюсы

- Современный и приятный интерфейс.
- Удобный SQL Editor.
- Хорош для просмотра и редактирования данных.
- Поддерживает несколько СУБД.
- Удобнее pgAdmin для повседневной работы с запросами.
- Меньше визуальной сложности.
- Хорошо подходит разработчикам, которым не нужны десятки административных функций PostgreSQL.

### Минусы

- Не настолько глубоко интегрирован с PostgreSQL, как pgAdmin.
- Некоторые продвинутые возможности зависят от редакции Beekeeper Studio.
- Если задача именно в администрировании PostgreSQL, pgAdmin обычно предоставляет больше специализированных возможностей.
- Для очень простого «посмотреть пару таблиц» всё равно сложнее Adminer.

### Когда выбирать

Если в основном хочется **писать SQL, смотреть таблицы и удобно работать с данными**, а не заниматься глубоким администрированием PostgreSQL.

# CloudBeaver

Web-версия экосистемы DBeaver. Предназначена для работы с базами данных непосредственно из браузера.

### Docker Compose

```yaml
cloudbeaver:
  image: dbeaver/cloudbeaver:latest
  container_name: cloudbeaver

  ports:
    - "8978:8978"

  restart: unless-stopped
```

После запуска:

```text
http://localhost:8978
```

При первом запуске CloudBeaver предложит выполнить первоначальную настройку.

### Плюсы

- Полноценный web-интерфейс.
- Поддерживает разные СУБД.
- Хороший SQL Editor.
- Просмотр и редактирование данных.
- Фильтрация результатов.
- Возможности импорта/экспорта данных.
- Подходит для централизованного доступа через браузер.
- Удобнее, если с базами работает несколько человек.
- Хороший компромисс между простотой и функциональностью.

### Минусы

- Тяжелее Adminer.
- Требует первоначальной настройки.
- Для одного разработчика и одной PostgreSQL-базы может быть избыточным.
- Часть возможностей экосистемы CloudBeaver относится к коммерческим редакциям.
- Более сложная конфигурация, если нужен просто временный UI для локальной БД.

### Когда выбирать

Если нужен **универсальный полноценный web-клиент**, особенно для нескольких баз данных или нескольких пользователей.

# Adminer

Очень лёгкий web-интерфейс для управления базами данных.

Главная идея Adminer — предоставить основные возможности работы с БД без развёртывания большого административного приложения.

### Docker Compose

```yaml
adminer:
  image: adminer:latest
  container_name: adminer

  ports:
    - "8080:8080"

  restart: unless-stopped
```

После запуска:

```text
http://localhost:8080
```

Для PostgreSQL из того же Compose:

```text
System: PostgreSQL
Server: db
Username: <POSTGRES_USER>
Password: <POSTGRES_PASSWORD>
Database: <POSTGRES_DB>
```

### Плюсы

- Очень простой запуск.
- Минимальная конфигурация.
- Лёгкий.
- Поддерживает PostgreSQL, MySQL, MariaDB, SQLite, MS SQL и другие СУБД.
- Можно просматривать и редактировать данные.
- Можно выполнять произвольные SQL-запросы.
- Есть импорт и экспорт.
- Отлично подходит как временный development-инструмент.

### Минусы

- Интерфейс значительно проще pgAdmin, Beekeeper и CloudBeaver.
- Меньше специализированных инструментов администрирования PostgreSQL.
- Не лучший вариант для сложной ежедневной работы с большой БД.
- SQL Editor довольно базовый.
- Меньше возможностей для организации множества подключений.

### Когда выбирать

Если нужен принцип:

> **`docker compose up` → открыть браузер → посмотреть базу → закрыть.**

Для небольшого development-окружения это один из самых простых вариантов.

# Что выбрать?

### Нужен полноценный PostgreSQL admin

```text
pgAdmin
```

Подходит для управления PostgreSQL, схемами, ролями, backup/restore и другими PostgreSQL-specific возможностями.

### Нужен удобный SQL-клиент

```text
Beekeeper Studio
```

Подходит для ежедневной разработки, просмотра данных и написания запросов.

### Нужен серьёзный универсальный web-интерфейс

```text
CloudBeaver
```

Особенно полезен при нескольких СУБД или нескольких пользователях.

### Нужен максимально простой development UI

```text
Adminer
```

Минимум конфигурации и быстрый доступ к базе.

# Рекомендация для development

Если проект использует PostgreSQL, обычно достаточно выбрать **один** инструмент.

Для простого локального проекта:

```text
PostgreSQL + Adminer
```

Для более серьёзной работы с возможностями PostgreSQL:

```text
PostgreSQL + pgAdmin
```

Нет особого смысла одновременно запускать pgAdmin, Beekeeper, CloudBeaver и Adminer — они в значительной степени решают одну и ту же задачу разными способами.

Также удобно держать DB UI отдельно от production-конфигурации, например:

```text
compose.yaml
compose.dev.yaml
compose.prod.yaml
compose.admin.yaml
```

Тогда административный интерфейс можно поднимать только когда он нужен:

```bash
docker compose -f compose.yaml -f compose.admin.yaml up -d
```

## Безопасность

Не храните реальные production-пароли непосредственно в Compose-файле:

```yaml
PGADMIN_DEFAULT_PASSWORD: adminpassword
```

Для локальной разработки это может быть допустимо с тестовыми credentials, но секреты production лучше передавать через environment variables, `.env`, Docker secrets или используемый в инфраструктуре secret manager.

Также не следует без необходимости публиковать административные web-интерфейсы базы данных в интернет.
